# Schedule Organiser — Design Spec

**Date:** 2026-08-03  
**Status:** Approved by user

---

## Overview

A self-hosted, personal-first smart schedule organiser. The user pastes or speaks free-form text (meeting notes, brain dumps, emails) and the system uses a configurable AI model to extract tasks, subtasks, dates, deadlines, and auto-generated descriptions. Tasks are managed via a web UI, synced to Google Calendar, and sent as notifications to Slack and/or Discord.

---

## Goals

- Fast, low-friction task capture from natural language (text or voice)
- AI-powered extraction of structure: tasks, subtasks, descriptions, dates, deadlines
- Personal-first ownership with optional read-only sharing of tasks with others
- Self-hosted, free to run (SQLite, no managed infrastructure required)
- Integrates with tools the user already uses: Google Calendar, Slack, Discord

---

## Non-Goals

- Multi-user accounts with separate workspaces (not in scope for v1)
- Real-time collaboration or task assignment
- Mobile-native apps (responsive web is sufficient)
- Built-in billing or SaaS hosting

---

## Architecture

### Repository Structure

Single monorepo:

```
schedule_organiser/
├── backend/        # FastAPI (Python)
├── frontend/       # React
├── docs/
└── README.md
```

### Layers

1. **Input Layer** — free-form text box + browser-based voice-to-text (Web Speech API)
2. **AI Parsing Layer** — configurable: user supplies their own API key and selects a provider (OpenAI, Anthropic Claude, or any OpenAI-compatible endpoint). The backend sends a structured prompt and receives tasks as JSON.
3. **Core Backend** — FastAPI REST API with SQLite via SQLAlchemy. Handles task CRUD, subtasks, and share link generation.
4. **Integrations** — Google Calendar API (OAuth 2.0, full read/write), Slack webhook, Discord webhook.
5. **Frontend** — React SPA served by the backend (or separately in dev). Main dashboard, input UI, task detail views, settings page.

## Data Model

### Task

| Field | Type | Notes |
|---|---|---|
| id | UUID | Primary key |
| title | string | Required |
| description | text | Auto-generated by AI, editable |
| status | enum | `pending`, `in_progress`, `done` |
| priority | enum | `low`, `medium`, `high` |
| due_date | datetime | Optional |
| scheduled_date | datetime | Optional (can be set later) |
| google_event_id | string | Nullable, set after calendar sync |
| share_token | string | Nullable, UUID for read-only sharing |
| created_at | datetime | Auto |
| updated_at | datetime | Auto |

### Subtask

| Field | Type | Notes |
|---|---|---|
| id | UUID | Primary key |
| task_id | UUID | FK → Task |
| title | string | Required |
| done | bool | Default false |
| order | int | Display order |

### Settings (single-row config table)

| Field | Type | Notes |
|---|---|---|
| ai_provider | string | `openai`, `anthropic`, `custom` |
| ai_api_key | string | Encrypted at rest |
| ai_model | string | e.g. `gpt-4o`, `claude-3-5-sonnet` |
| ai_base_url | string | For custom/OpenAI-compatible endpoints |
| slack_webhook_url | string | Nullable |
| discord_webhook_url | string | Nullable |
| google_calendar_id | string | Nullable |
| google_oauth_token | text | Encrypted, stores OAuth token JSON |

## Components

### Backend (FastAPI + Python)

- `main.py` — app entry point, mounts routers
- `routers/tasks.py` — task CRUD endpoints
- `routers/parse.py` — POST `/parse`: accepts raw text, calls AI, returns structured tasks for preview before saving
- `routers/integrations.py` — Google Calendar sync, Slack/Discord webhook triggers
- `routers/settings.py` — read/write settings
- `routers/share.py` — generate and resolve read-only share tokens
- `services/ai_parser.py` — AI provider abstraction; sends prompt, parses response to task schema
- `services/calendar.py` — Google Calendar OAuth flow and event CRUD
- `services/notifications.py` — sends formatted messages to Slack and/or Discord webhooks
- `models.py` — SQLAlchemy models
- `database.py` — SQLite connection setup
- `config.py` — loads env vars (DB path, secret key for encryption)

### Frontend (React)

- **Dashboard** — list of all tasks, filterable by status/priority/date, inline subtask toggle
- **Input Panel** — text area + voice record button; "Parse" button sends to backend; preview parsed tasks before saving
- **Task Detail** — full task view, editable description, subtask management, dates, sync status
- **Settings Page** — configure AI provider/key/model, Slack webhook, Discord webhook, Google Calendar OAuth connect
- **Share View** — read-only task view accessible via share link (no auth required for viewer)

## AI Parsing

The backend sends the user's raw text to the configured AI provider with a structured system prompt instructing it to return a JSON array of tasks. Each task includes:

- `title`
- `description` (auto-generated, 1–3 sentences)
- `subtasks` (array of strings)
- `due_date` (ISO 8601 or null)
- `scheduled_date` (ISO 8601 or null)
- `priority` (`low`, `medium`, `high`)

The frontend shows the parsed result as a preview (editable) before the user confirms saving. This prevents bad AI output from going straight to the database.

---

## Notifications

When a task is created or updated, the backend can fire webhooks to Slack and/or Discord. The message includes task title, description summary, due date, and a link to the task. Webhooks are optional — if a URL is not configured, that notification is silently skipped.

Notification triggers:
- Task created (from parse + confirm)
- Task marked done
- Task due date is tomorrow (daily cron job)

---

## Google Calendar Integration

- OAuth 2.0 flow: user clicks "Connect Google Calendar" in settings, is redirected to Google consent screen, token stored in Settings table (encrypted).
- On task save (with a date): backend creates a Google Calendar event and stores `google_event_id` on the task.
- On task update (date changed): backend updates the existing event.
- On task deleted: backend deletes the event.
- On task marked done: event is optionally removed or left as-is (configurable).

---

## Sharing

The owner can generate a share link for any task. The link contains a `share_token` (UUID). Anyone with the link can view the task and its subtasks in read-only mode — no login required. The owner can revoke the token at any time.

---

## Error Handling

- AI parse failures return a user-visible error with the raw AI response, so the user can retry or paste manually.
- Google Calendar auth errors surface in the UI with a "Reconnect" button.
- Webhook failures are logged but do not block task creation.
- All API errors return structured JSON `{ "error": "...", "detail": "..." }`.

## Configuration & Setup

The app is configured via a `.env` file:

```
DATABASE_URL=sqlite:///./schedule.db
SECRET_KEY=<random string for encryption>
```

All other settings (API keys, webhooks, calendar) are managed through the in-app Settings page and stored in the database. The user does not need to edit `.env` for integrations.

Setup steps:
1. `pip install -r requirements.txt` (backend)
2. `npm install && npm run build` (frontend)
3. Copy `.env.example` to `.env`, set `SECRET_KEY`
4. `uvicorn backend.main:app` — serves both API and built frontend
